# Agent 桌面端 Codex 风格 UI 重构设计

日期：2026-07-17

## 目标

将现有 Tauri + React 桌面端整体重构为接近 Codex App 的设计系统与交互结构，同时完整保留项目已有的聊天、项目管理、模型选择、工具调用、Skills、MCP、设置、文件、Git、终端、SSH、隧道、自动化、记忆和远程连接能力。

产品品牌由 Live Agent 更名为 **Agent**。应用不使用 OpenAI、Codex 的名称、商标或图形标志，只借鉴其界面设计语言和信息组织方式。

## 设计原则

1. **功能优先**：现有能力全部保留，界面围绕真实功能重新组织，不为视觉模仿隐藏或削弱功能。
2. **安静的工作区**：减少光晕、渐变、彩色装饰和夸张圆角，让任务、代码、工具结果成为视觉主体。
3. **统一层级**：聊天、设置、Skills、MCP 和项目工具共享同一套颜色、间距、圆角、阴影、字体与交互状态。
4. **渐进呈现**：文件、Git、终端、SSH 和隧道按需打开；工具调用、思考过程、子 Agent 和文件变更默认展示摘要，可继续展开。
5. **跨平台一致**：浅色、深色、Windows 自定义标题栏和 macOS 原生标题栏空间均纳入设计。

## 品牌

### 名称

应用名称统一为 `Agent`，替换界面文案、窗口标题、应用配置、安装包信息和关于页面中的 `LiveAgent`、`Live Agent` 展示名称。代码内部不要求为品牌目的重命名稳定的包名、存储键或协议字段，避免破坏兼容性。

### 图标

创建一个原创的单色几何 A 图标：两条相向路径构成字母轮廓，中间保留类似终端光标的负空间。图标必须满足：

- 小尺寸下仍可辨认；
- 浅色与深色背景均有对应版本；
- 不复制 OpenAI 结形标志；
- 同步用于桌面应用图标、标题栏、欢迎页、关于页面和安装资源。

## 整体信息架构

桌面端采用三段式工作区：

```text
┌──────────────┬─────────────────────────────┬──────────────┐
│ 全局侧栏      │ 当前任务主工作区             │ 上下文工具面板 │
│              │                             │              │
│ 新任务        │ 顶栏：项目、任务、模型、状态   │ 文件          │
│ 项目          │                             │ Git           │
│ 最近任务      │ 对话、工具调用、变更结果       │ 终端          │
│              │                             │ SSH / 隧道    │
│ Skills / MCP │ 底部悬浮输入工作台            │              │
│ 应用菜单      │                             │              │
└──────────────┴─────────────────────────────┴──────────────┘
```

### 全局侧栏

- 默认宽度约 260px，可折叠。
- 顶部仅展示紧凑 Agent 标识和“新任务”操作，不使用大型品牌标题。
- 主体包含项目列表与最近任务，继续支持折叠、固定、重命名、删除、分享、活动状态和虚拟滚动。
- Skills 与 MCP 移到侧栏下方的全局导航区。
- 设置、主题切换、应用更新和关于入口合并进左下角应用菜单。
- 中等窗口允许折叠；小窗口以覆盖式抽屉展示。

### 主工作区

- 顶栏高度约 44px，仅保留当前项目、任务标题、模型选择、运行状态和打开工具面板的入口。
- 对话内容保持居中阅读宽度，代码、表格、Diff 和工具结果允许在可用空间内扩展。
- 底部输入区作为悬浮工作台存在，不与页面边缘形成厚重固定栏。
- Windows 自定义标题栏与应用顶栏视觉融合；macOS 保留交通灯区域。

### 上下文工具面板

- 文件、Git、终端、SSH、隧道和后台任务共享右侧面板与标签栏。
- 面板默认关闭，可固定、关闭、调整宽度，并保留现有每项目状态。
- 宽屏并排显示；中等和小窗口改为覆盖式抽屉，避免压缩主对话区。

## 视觉系统

### 字体

- 正文：系统无衬线字体，中文回退至 PingFang SC、Microsoft YaHei 等平台字体。
- 标题与关键操作：项目现有 OpenAI Sans Semibold，仅作为字体资源使用。
- 代码、路径、终端和数值：平台等宽字体栈。

### 颜色

浅色主题：

- 主工作区接近纯白；
- 侧栏为轻微暖灰；
- 浮层为不透明或轻透明的中性表面；
- 边框采用低对比中性灰；
- 正文使用深灰而非纯黑。

深色主题：

- 主背景改为中性炭黑，移除当前明显的蓝色倾向；
- 侧栏、输入框和浮层通过小幅明度差建立层级；
- 边框保持低对比，避免每个区域都出现明显描边。

状态色保持克制：运行和成功使用绿色，警告使用橙色，错误和危险操作使用红色。导航图标默认使用中性色，不以多色图标区分页面。

### 形状与层级

- 列表项和普通按钮圆角为 6–8px；
- 输入框、卡片和菜单圆角为 10–14px；
- 除状态徽标外减少胶囊形按钮；
- 常驻区域不使用投影；
- 菜单、抽屉、对话框和悬浮输入框使用柔和投影；
- 减少玻璃拟态，仅在确实悬浮于内容上方的组件使用轻度模糊。

### 动效

- 侧栏、工具面板、菜单与抽屉使用 160–220ms 的统一缓动；
- 删除欢迎页大面积光晕、漂浮、渐变文字与彩色聚光效果；
- 保留流式响应、加载、终端运行、任务排队等信息性动效；
- 遵循 `prefers-reduced-motion`。

## 核心页面与交互

### 任务与聊天

- 用户界面中的“新对话”改为“新任务”，历史数据语义保持兼容。
- 用户消息使用紧凑的浅色消息块；助手消息以自然文档流展示。
- 工具调用、思考过程、上下文压缩、文件变更和子 Agent 状态使用统一的可折叠事件行。
- 事件行默认显示图标、动作、目标、状态和耗时；详细输出按需展开。
- 消息操作在悬停或键盘聚焦时显示，移动/触控布局保留可发现入口。

### 输入工作台

- 第一层承载多行输入、粘贴内容和附件预览。
- 第二层承载上传、Skills、搜索、运行模式、推理级别、队列状态和发送/停止按钮。
- 模型选择器移至顶栏；与模型相关的推理选项仍在输入区附近显示。
- 现有排队发送能力保留，队列收纳为输入框上方的紧凑列表。
- 拖放上传、粘贴文件、提及文件和大段文本处理保持不变。

### 欢迎与空状态

- 使用小型 Agent 标识和简短任务提示替换发光英雄区。
- 提供最近项目和少量真实任务入口，不使用彩色营销卡片。
- 无模型、无项目、无 Skills、无 MCP 和连接失败等状态均明确说明下一步操作。

### Skills 与 MCP

- 两者共享管理页面框架：顶部标题与操作，左侧筛选/分类，右侧列表或详情。
- 移除独立 Hub 页面中过度的玻璃、光效、渐变与卡片入场动画。
- 安装、启用、连接、刷新、错误和空状态使用统一组件。

### 设置

- 设置页采用左侧分类导航、右侧表单内容的两栏布局。
- 供应商、系统、远程、SSH、记忆、Hooks、Cron、Agents 和关于页面共享标题、分组、表单行和危险操作规范。
- 保存、加载、验证、连接错误就近显示；全局提示只用于跨页面结果。
- 窄窗口下分类导航改为顶部选择器或抽屉。

### 编辑器与覆盖层

- 文件预览、代码编辑、Markdown、图片和 SSH 终端覆盖层统一为编辑器工作区结构。
- 保留 Monaco、文件预览和现有打开/关闭行为，只重做顶部工具栏、边框、背景和响应式布局。

## 组件与代码组织

重构优先建立共享视觉基础，而不是在每个页面继续堆叠长串工具类：

- 在全局 CSS 中建立 Agent 颜色、表面、边框、阴影、布局和状态令牌；
- 扩展现有 `components/ui` 基础组件，统一按钮、图标按钮、输入框、菜单、对话框、标签、分段控件和状态提示；
- 将应用壳、全局侧栏、主顶栏和右侧上下文面板拆为清晰边界；
- 保留聊天运行、侧栏 Store、项目状态、终端会话、Git、Skills 和 MCP 的现有数据接口；
- 对超长组件进行与本次界面改造直接相关的局部拆分，不进行无关后端重构。

## 数据流与状态

- `App` 继续负责全局设置、主题和顶层页面状态；
- 聊天、历史、项目和右侧面板继续使用现有 Store 与设置持久化；
- 导航重组只改变入口和呈现，不更改历史记录格式、网关协议和后端命令；
- 旧品牌名相关的持久化键、包名和协议标识若影响兼容性则保留，仅修改用户可见品牌；
- 面板折叠、宽度、活动标签和项目选择继续持久化。

## 错误处理与可访问性

- 错误信息说明发生了什么以及用户可以采取的动作；
- 危险操作保留明确确认流程；
- 所有图标按钮具有可访问名称与提示；
- 键盘焦点清晰可见，菜单、抽屉、对话框可完整键盘操作；
- 颜色不是状态的唯一表达方式；
- 窄窗口、触控和减少动效设置均纳入实现。

## 实施边界

本次允许：

- 重组导航、按钮位置和部分交互；
- 调整页面组件结构；
- 重做全局主题和基础组件；
- 创建新品牌图标并替换用户可见品牌资源；
- 为直接服务界面重构而拆分部分大型组件。

本次不做：

- 删除或弱化现有功能；
- 修改后端协议、聊天数据格式或核心 Agent 执行逻辑；
- 引入与当前功能无关的新业务模块；
- 使用 Codex/OpenAI 商标、名称或图形标志。

## 验证与验收

实施完成后至少执行：

1. TypeScript 与 Vite 生产构建；
2. 现有前端测试集；
3. Biome 检查；
4. 聊天发送/停止/排队、历史切换、项目切换、文件上传、模型选择回归；
5. Skills、MCP、设置、文件、Git、终端、SSH 和隧道关键入口回归；
6. 浅色与深色主题检查；
7. 宽屏、中等窗口和小窗口布局检查；
8. Windows 标题栏与 macOS 标题栏空间检查；
9. 关键页面截图审查，重点检查密度、对齐、对比度、溢出和交互状态。

验收标准：整个桌面端呈现统一、克制、接近 Codex App 的工作台体验；现有功能可继续访问和使用；浅色与深色均完整；品牌统一为 Agent；不出现 OpenAI/Codex 商标混淆。
