# Agent 项目完整学习手册设计说明

## 1. 文档目标

为 `Agent` 仓库编写一套可连续学习、也可按功能查阅的中文源码学习手册。手册应帮助一名已经熟悉 TypeScript 与 React、但不一定熟悉 Rust、Go、Tauri 和 Agent Runtime 的开发者，逐步建立对整个项目的完整认识，并具备定位、调试和扩展核心功能的能力。

文档必须以当前仓库源码、配置和测试为事实依据。现有文档可作为线索，但不能替代源码验证。

## 2. 目标读者

目标读者具备以下基础：

- 能阅读 TypeScript、React 组件和常见异步代码；
- 理解 HTTP、WebSocket、事件、状态管理和基本数据库概念；
- 不要求预先掌握 Rust、Go、Tauri、MCP 或 Agent Tool Loop；
- 希望通过阅读文档后，能够继续独立阅读源码和实现功能修改。

涉及 Rust、Go、Tauri 和 Agent 专有概念时，正文先解释项目中实际使用到的最小知识，再进入源码实现，不展开与本项目无关的语言教程。

## 3. 交付形式

学习手册位于 `docs/learning/`，采用“总览索引 + 分模块手册”的结构。

总览索引负责：

- 说明项目用途、技术栈和运行单元；
- 给出章节之间的依赖关系和推荐学习顺序；
- 提供按功能、按技术栈和按源码目录三种导航方式；
- 汇总开发、测试、构建与排障命令；
- 标记不同读者可以跳过或重点阅读的章节。

分模块手册负责深入解释具体功能。每份文件保持单一主题，避免形成难以导航的单篇超长文档。

## 4. 教学组织方案

采用“学习路径与功能域结合”的组织方式，而不是单纯按编程语言或源码目录罗列。

整体顺序为：

1. 先建立项目全局心智模型；
2. 再追踪一次 Agent 请求的端到端生命周期；
3. 按用户功能和核心能力深入各模块；
4. 最后补充测试、构建、发布、调试和扩展方法。

这种方式既能解释跨越 React、Tauri/Rust 和 Go Gateway 的完整调用链，也能让读者在后续开发时按功能快速查阅。

## 5. 计划覆盖的章节

手册至少覆盖以下主题，最终文件拆分可在源码盘点后按模块边界微调，但不得遗漏对应内容：

1. 项目导读、学习地图和术语；
2. 开发环境、依赖安装、运行方式和首个调试会话；
3. 仓库目录、总体架构、进程边界和平台差异；
4. 一次 Agent 请求从输入到持久化的完整生命周期；
5. React 应用入口、页面组织、应用外壳和主要 UI 状态；
6. Chat Runtime、回合队列、流式事件和消息渲染；
7. 模型 Provider、请求适配、Thinking、搜索和附件；
8. Builtin Tools、工具注册、执行循环、审批和安全边界；
9. Skills 的发现、校验、安装、加载和渐进式披露；
10. MCP 配置、连接、工具发现、调用与运行时管理；
11. Memory 的提取、召回、写入、整理、配额和存储；
12. History、上下文压缩、摘要检查点、文件账本和恢复；
13. Subagents 的调度、消息总线、状态持久化和工具集成；
14. Hooks、Todo、Cron 与自动化任务；
15. 工作区文件树、编辑器、预览和文件变化追踪；
16. 终端、后台进程、Git、SSH、SFTP 和隧道；
17. 设置系统、配置同步、国际化和本地数据；
18. Tauri/Rust 命令层、Runtime 层和 Services 层；
19. Go Gateway、远程连接协议、同步机制和 Web UI；
20. 测试体系、静态检查、构建、桌面打包和发布；
21. 综合排障方法、源码阅读路线和后续扩展指南。

## 6. 单项功能的讲解模板

每项用户功能或核心能力统一回答以下问题：

### 6.1 功能定位

- 它解决什么问题；
- 用户从哪里触发；
- 它与其他功能的关系是什么。

### 6.2 实现边界

- 涉及哪些 React/TypeScript、Tauri/Rust、Go 模块；
- 每一层负责什么；
- 哪些能力仅在桌面端、远程端或特定平台可用。

### 6.3 完整实现方案

- 从入口事件到最终结果的调用链；
- 核心函数、类型、状态和事件；
- 前后端或进程间通信方式；
- 数据如何读取、转换、流转、持久化和回显；
- 异步任务、并发控制、取消、重试和资源清理方式；
- 关键代码路径及其在整体方案中的作用。

### 6.4 设计亮点与取舍

- 为什么使用当前分层和抽象；
- 当前设计解决了哪些复杂性或安全问题；
- 哪些约束来自跨平台、并发、持久化或兼容性需求；
- 当前方案的代价、边界和容易误改的位置。

### 6.5 异常与安全

- 输入校验、权限审批和访问边界；
- 错误如何传播到调用方和 UI；
- 中断、超时、断线、部分成功及恢复策略；
- 涉及文件、命令、网络和凭据时的安全措施。

### 6.6 验证与扩展

这一部分保持简洁，仅列出：

- 最关键的测试文件和验证命令；
- 扩展该功能时最重要的修改入口；
- 一个简短练习或思考题。

## 7. 图示与代码引用规范

复杂关系使用 Mermaid 图示，并优先选择最能说明问题的形式：

- 架构图：表达进程、模块和职责边界；
- 时序图：表达请求、工具调用、远程同步等时间过程；
- 流程图：表达审批、重试、压缩、记忆提取等分支逻辑；
- 状态图：表达会话、任务或连接的状态变化。

代码引用遵循以下原则：

- 给出仓库相对路径和关键符号名；
- 仅引用有助于理解的短代码片段，不大段复制源码；
- 解释代码在调用链中的作用，而不只做语法翻译；
- 对可能随代码变动的行号保持克制，优先使用稳定的类型、函数和模块名定位。

## 8. 源码分析方法

每个模块的结论至少通过以下信息交叉验证：

1. 应用入口、注册表或路由入口；
2. 核心实现文件及其直接依赖；
3. 调用该模块的上游代码；
4. 该模块调用的下游接口；
5. 对应测试、配置或协议定义；
6. 必要时通过构建或测试命令验证。

对于前端和后端存在同名概念的功能，必须分别说明其职责，不能将 TypeScript 客户端封装、Tauri command 和 Rust service 混为一层。

## 9. 准确性与验证要求

完成文档后执行以下检查：

- 检查所有文档链接和源码路径是否存在；
- 检查术语、类型名、函数名和事件名是否与当前源码一致；
- 检查 Mermaid 代码块和 Markdown 结构；
- 验证文档中的安装、运行、测试和构建命令；
- 对照源码目录和功能入口检查覆盖范围；
- 区分已经实现、受平台限制、依赖外部服务和仅存在设计文档的能力；
- 不把测试假设、旧文档或计划中的功能误写成当前已实现行为。

## 10. 范围边界

本文档讲解“每项用户功能与核心模块”，不逐个解释仓库中的所有函数、样式组件、生成文件或第三方依赖源码。

以下内容只在影响项目理解时说明：

- 通用 UI 基础组件的每个样式属性；
- 自动生成的锁文件、图标和平台资源；
- 第三方库内部实现；
- 与当前功能无关的语言基础知识。

现有 `docs/tutorials/liveagent-main-features-guide.md` 作为可参考资料保留。新手册应覆盖整个仓库并补足其未涉及或不够深入的模块，不直接覆盖用户已有文档。

## 11. 完成标准

当以下条件全部满足时，学习手册视为完成：

- `docs/learning/README.md` 能作为完整导航入口；
- `agent-gui`、`agent-gui/src-tauri`、`agent-gateway` 和工程脚本均有对应讲解；
- 每项主要用户功能均包含实现方案、调用链、数据流、设计亮点和异常边界；
- 跨层功能能从 UI 入口追踪到实际执行与持久化位置；
- 读者能够依据文档运行项目、跟踪一次请求、定位功能源码并完成小型扩展；
- 路径、命令和关键技术结论通过自动检查或人工交叉验证。
